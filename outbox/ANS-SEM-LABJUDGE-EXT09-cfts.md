## ① CIRC重做立项（主线B见证证书化内嵌A，C仅探针，AC1–AC5）

**路线选择稳健性：中高。**
把主线压在 B 的「见证证书化」上，同时让 A 内嵌、C 退为探针，这是典型的**收敛式重构**：先固化可信主路径，再把旁支降权。稳健点在于它避免了「A/B/C 三线并行争夺验收话语权」的常见失稳。风险点是：若 B 的证书化本身尚未定型，内嵌 A 会把 A 的历史包袱焊进主契约，回头难拆。

**机器可复核性：取决于 AC1–AC5 的定义形态。**
若 AC1–AC5 是可枚举的断言（输入→输出、证书字段存在性、探针触发计数），可以机器复核。若含「合理」「充分」这类形容词，则不可。**建议强制 AC 全部落为布尔谓词或可采样统计量。**

**制度漏洞：**
- 「C 仅探针」缺少**探针不得反向影响主线判定**的硬约束，否则 C 会事实上升格为第二主线。

## ② 缓存锚域限条款（fallthrough DONE 四条件 + BLOCKED 四触发 + 缓存锚≠内容认证）

**这是三案中制度风险最高的一案。**

**路线选择稳健性：中。**
「缓存锚 ≠ 内容认证」是正确且必要的切割，方向对。但把 DONE 绑定到 fallthrough 四条件、BLOCKED 绑定到四触发，等于用**两套离散开关**决定状态——边界必须互斥且穷尽，否则出现灰区。

**机器可复核性：可，前提是四条件/四触发为合取/析取明确式。**
若 DONE = (c1∧c2∧c3∧c4)，BLOCKED = (t1∨t2∨t3∨t4)，则可判。若存在「部分满足」，即不可判。

**制度漏洞（重点）：**
1. **DONE/BLOCKED 非互斥风险**：若某情形同时满足一个 DONE 条件与一个 BLOCKED 触发，规则未定优先级 → 状态机死锁或任意裁决。**必须补：BLOCKED 优先于 DONE，或显式定义冲突消解。**
2. **四条件未覆盖的第五态**：既不 DONE 也不 BLOCKED 时是什么？若默认 fallthrough（回落），则等于**默认放行**，是安全漏洞。应改为默认 BLOCKED 或 PENDING。
3. **缓存锚≠内容认证**虽写了，但未说明**缓存锚被污染时的失效路径**：锚有效但内容已变，谁负责降级？缺此条，等于只声明了不等价，没声明不等价时的行为。
4. **BLOCKED 四触发若含「缓存不可用」类系统态**，会把**基础设施抖动误判为内容问题**，需要区分「暂不可用（重试）」与「不可信（阻断）」。

**本项倾向：fail（须修订）** —— DONE/BLOCKED 互斥与默认态是硬缺口，不修不可过。

## ③ A1堆叠升级（L0确权锁边界，L1/L2契约JSON化，DISPUTED停层）

**路线选择稳健性：高。**

**机器可复核性：高。**
JSON 契约天然可机器校验（schema 校验、字段约束）。DISPUTED 停层只要定义「进入 DISPUTED 的谓词」和「停层时不向下传递」即可机器执行。

**制度漏洞：**
1. **停让规则的方向性**：DISPUTED 停层是「停止升级」还是「停止一切处理」？若只停升级，L2 仍在跑，可能产出被争议污染的中间结果。**需明确 DISPUTED 时 L1/L2 是否冻结。**
2. **层级停让的解除条件缺失**：谁、凭什么把状态从 DISPUTED 解回？无解除规则则永久卡层。
3. **L0 锁边界 vs L1/L2 契约**：若 L1 契约与 L0 边界冲突，谁优先？应写明 L0 优先且 L1/L2 契约须通过 L0 边界校验。
