## 问1：三焊缝中哪条对你线领域最有实质推进力？最小动作

**最有推进力：焊缝① 数值锚 → Lean 可验证陈述。**

原因很窄：你线关心的是证书生命周期。证书要跨态迁移，第一步不是找启发式，也不是防幻觉，而是**把“残差小于阈值”这类数值事实，变成 Lean 里可检查的命题**。否则五态机里的“已验证”态没有类型级含义，只是日志态。

**可落地最小动作：**

> 选一个你现有 PINN 里最小的标量输出，例如某点残差 `r(x0)`，写一个 Lean 定义：
> `def residual_ok (r : Float) : Prop := r < 1e-3`
> 再加一个**外部数值证书接口**：Python 端算出 `r(x0)=...`，导出为 JSON；Lean 端不直接信 Float，而是接收 `Rat` 或有理区间，证明 `residual_ok q`。
> 动作验收：`#check residual_ok` 通过，且一条 `example : residual_ok (1/2000) := by norm_num` 能编译。

这不是形式化整个 PINN，而是先把**一个数值锚点**接进 Lean 可验证陈述。焊缝①的实质推进力就在这里：它让“数值满足”第一次有资格进入证书五态机的候选证明态。

## 问2：焊缝②的重要性加权与联邦 default-deny 纪律是否兼容？

**结论：可兼容，但必须把“重要性加权”降级为提议排序，不能升格为授权规则。**

联邦 default-deny 的核心是：**未显式允许，即拒绝。**  
SHAP 因果重要性 → 证明搜索启发，本质是“哪些变量/子目标更值得先搜”。这可以兼容，因为启发式只影响**搜索顺序**，不影响**准入判定**。

兼容条件：

1. **加权只进 scheduler，不进 access control。**
   - SHAP 权重可以决定先试哪个 lemma、先展开哪个分支。
   - 但不能决定“这个假设是否可接受”。

2. **default-deny 作用在证明项上，不作用在搜索热度上。**
   - 一个高 SHAP 权重的子目标，若没有形式许可，仍然 deny。
   - 低权重但可被编译器接受的证明，仍然 allow。

3. **加权必须可审计、可撤销。**
   - 每次搜索启发使用 SHAP 权重，要记录来源、版本、数据切片。
   - 否则会变成“因为模型觉得重要，所以公理放行”，这就是 postulate 脚手架回潮。

冲突点：

- 若把 SHAP 重要性解释为“因果上必须为真”，就与 default-deny 冲突。  
  因为 SHAP 是模型行为归因，不是数学真值。
- 若联邦节点用全局 SHAP 权重绕过本地策略，也冲突。  
  本地 default-deny 必须优先于全局启发。

一句话：**SHAP 可以当搜索的油门，不能当证明的签证。**

## 问3：你线如何识别并熔断「postulate 脚手架」式假框架？

识别信号：

1. **有宏大名词，无小可执行单元。**
   - 例如“统一证明框架”“AI 证明三路”，但没有一条 `example` 能编译。

2. **公理直 postulate，证明是散文。**
   - Lean 里出现 `axiom`、`postulate`、`sorry` 作为主路径，而不是待消除的洞。
   - 论文里用自然语言说“可证明”，代码里没有 `#check` 闭环。

3. **type-in-type 或不一致底座。**
   - 声称形式化，但类型系统本身不健全。
   - 这会让你误以为“已形式化”，实际是“已修辞化”。

4. **无证书生命周期。**
   - 没有“候选→数值支持→形式候选→已验证→可撤销”的状态迁移。
   - 只有“我们提出一个框架”的静态宣称。

熔断动作：

> 设一条硬门：**任何声称“形式化证明”的模块，必须提交一个最小 Lean 文件，包含：**
> 1. 一个定义；
> 2. 一个可编译的 `example`；
> 3. 一个 `#print axioms` 输出，且不含 `sorryAx` 或未解释 postulate。
>
> 若拿不出，自动降级为“猜想脚手架”，不得进入证书五态机的“已验证”态。

这不是否定探索，而是**把探索锁在候选态**。假框架最怕的不是批评，是编译。

## 你线角：五态机与 PINN→CAP 能否同构建模？

可以，但要分清两层跃迁：

**证书五态机：**

1. 候选陈述  
2. 数值支持  
3. 形式候选  
4. 已验证  
5. 可撤销/失效

**PINN→CAP 的跃迁：**

- PINN 给的是数值满足：残差小、损失低、采样点上成立。
- CAP 要的是数学证明：全称量化、边界条件、稳定性、误差界。

同构建模的关键是：

> 把 PINN 输出当作五态机里的“数值支持态”证据，而不是“已验证态”证据。

也就是说：

- `数值满足` → 只能推进到态 2。
- `Lean 可验证陈述 + 编译通过` → 才能推进到态 4。
- `CAP` 是态 4 的一个特定证书类型：它要求从数值锚出发，经过形式化误差界或区间验证，得到全称命题。

可落地的最小同构：

```text
态1 candidate:   P(x) 在采样点上残差 < eps
态2 numerical:   Python 证书 + 数据切片 + 随机种子
态3 formal_candidate: Lean 命题 residual_ok q
态4 verified:    Lean 证明 + #print axioms 干净
态5 revoked:     新数值反例或公理污染，回退
```

PINN→CAP 的跃迁，就是**态2→态4**，但不是跳过去，而是必须经过态3。  
焊缝①就是把态2接到态3的那座桥。
